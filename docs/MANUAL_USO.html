1. Acceso a la aplicación

La aplicación se ejecuta localmente en dos servicios independientes:

ServicioURLFunción
Frontendhttp://localhost:5173Interfaz web que usas para navegar y registrar datos
Backend / APIhttp://localhost:3000API REST (Express + Prisma/SQLite); /health para verificar que está activo
Abre http://localhost:5173 en el navegador. Si no carga, verifica que ambos procesos (npm run dev en backend/ y en frontend/) estén corriendo — ver README.md del proyecto para instrucciones de arranque.

2. Inventario de sistemas de IA

La pantalla principal muestra una tabla con todos los sistemas de IA registrados en la organización:

ColumnaContenido
NombreNombre del sistema y, debajo, su propósito
ProviderProveedor del modelo/motor de IA (ej. Gemini, Vertex AI)
GCP ProjectID del proyecto GCP asociado, o — si no aplica
EstadoPill activo / pausado
RiesgosNúmero total de riesgos registrados
ControlesNúmero total de controles registrados
IncidentesNúmero total de incidentes registrados

Haz clic en cualquier fila para abrir la vista de detalle de ese sistema.

Si todavía no hay ningún sistema registrado, la tabla muestra el mensaje "Todavía no hay sistemas de IA registrados."

3. Registrar un nuevo sistema de IA

El formulario de alta está disponible junto al inventario. Campos:

NombreObligatorio. Nombre identificativo del sistema.
PropósitoObligatorio. Descripción breve de para qué se usa el sistema.
ProviderObligatorio. Proveedor del modelo de IA (ej. "Gemini (Vertex AI)").
GCP Project (opcional)ID del proyecto GCP, si aplica.
EstadoSelector: Activo o Pausado. Por defecto: Activo.

Al enviar el formulario, el botón Añadir sistema de IA cambia a "Creando…" mientras se procesa y se deshabilita para evitar envíos duplicados. Si algún campo obligatorio falla la validación del servidor, el error aparece debajo del campo correspondiente. Al crearse correctamente, el sistema aparece de inmediato en el inventario y el formulario se limpia.

4. Vista de detalle de un sistema

Al hacer clic en una fila del inventario se abre la vista de detalle, que muestra:

  • Un botón "← Volver al inventario" en la parte superior para regresar a la tabla.
  • El nombre del sistema junto a su pill de estado.
  • El propósito registrado.
  • Una línea con Provider y GCP Project (este último muestra — si no fue registrado).
  • La sección de Riesgos, con sus Controles y Evidencia anidados.
  • Un panel separado de Incidentes.
Cada vez que se registra un riesgo, control, evidencia o incidente nuevo, la vista completa se refresca automáticamente — no es necesario recargar la página ni salir del detalle para ver el cambio reflejado.

Estructura jerárquica de la sección de riesgos:

Riesgo (categoría, severidad, descripción)
  └─ Control (nombre, estado, dominio ISO)
      └─ Evidencia (tipo, contenido, registrado por, fecha)

Si el sistema no tiene ningún riesgo registrado todavía, se muestra el mensaje "Todavía no hay riesgos registrados."

5. Registrar un riesgo

Dentro del detalle de un sistema, el formulario "Añadir riesgo" tiene estos campos:

CategoríaSelector: sesgo, privacidad, seguridad, transparencia, robustez, otro. Por defecto: otro.
SeveridadSelector: bajo medio alto critico. Por defecto: bajo.
DescripciónObligatorio. Texto libre describiendo el riesgo.

Botón: Añadir riesgo (cambia a "Creando…" mientras se procesa). El nuevo riesgo aparece de inmediato como una tarjeta nueva en la lista.

6. Registrar un control

Dentro de cada tarjeta de riesgo hay un formulario "Añadir control":

NombreObligatorio.
EstadoSelector: planificado, implementado, verificado. Por defecto: planificado.
Dominio ISOSelector cargado dinámicamente con los 9 dominios del Anexo A de ISO/IEC 42001 (formato "{código} — {nombre}"). Si no se elige ninguno, toma el primero disponible por defecto.

Botón: Añadir control ("Creando…" mientras se procesa). Se deshabilita si todavía no hay dominios ISO cargados.

Regla anti-huérfano: el sistema no permite crear un control asociado a un dominio ISO que no exista. Si ocurre este error, se muestra debajo del selector de dominio.

7. Registrar evidencia

Dentro de cada tarjeta de control hay un formulario "Añadir evidencia":

TipoSelector: texto, enlace, archivo. Por defecto: texto.
ContenidoObligatorio. El texto, URL o referencia de la evidencia.
Registrado porObligatorio. Nombre de quien registra la evidencia.

Botón: Añadir evidencia ("Guardando…" mientras se procesa). Cada evidencia se muestra con su tipo, contenido y la línea "{registrado por} · {fecha}".

Registrar evidencia en un control es lo que hace que ese dominio ISO sume puntos en el dashboard de madurez — un control sin evidencia no cuenta para el score.

8. Registrar un incidente

El panel "Incidentes", separado de la lista de riesgos, tiene su propio formulario:

DescripciónObligatorio.
SeveridadSelector, mismas 4 opciones que en riesgos. Por defecto: bajo.
Fecha de ocurrenciaObligatorio. Selector de fecha.
Fecha de resoluciónOpcional. Selector de fecha — dejar vacío si el incidente sigue abierto.

Botón: Añadir incidente ("Guardando…" mientras se procesa). Cada incidente muestra su pill de severidad, la descripción, "Ocurrido: {fecha}" y, si aplica, "· Resuelto: {fecha}".

Si no hay incidentes registrados, se muestra "No se han registrado incidentes."

9. Filtros de severidad y dominio

En la vista de detalle, dos selectores permiten acotar lo que se muestra:

FiltroOpcionesEfecto
Severidad"Todas" + bajo/medio/alto/criticoMuestra solo las tarjetas de Riesgo con esa severidad
Dominio ISO"Todos" + los 9 dominios ("{código} — {nombre}")Dentro de cada riesgo visible, muestra solo los Controles de ese dominio

Ambos filtros se pueden combinar y se aplican de forma independiente. Mensajes cuando no hay coincidencias:

  • "Ningún riesgo coincide con los filtros seleccionados." — el filtro de severidad deja la lista de riesgos en cero.
  • "Ningún control coincide con el dominio seleccionado." — un riesgo visible no tiene controles del dominio elegido.

10. Dashboard de madurez

Muestra un gráfico de barras con el score de madurez (0–100%) de cada uno de los 9 dominios del Anexo A de ISO/IEC 42001.

Fórmula: cobertura = controles con evidencia registrada ÷ total de controles del dominio.

El dashboard distingue visualmente dos situaciones que, con un score de 0%, serían indistinguibles:

ColorSignificado
AzulScore calculado — el dominio tiene al menos un control registrado; la barra refleja el % real de cobertura con evidencia.
GrisSin datos — el dominio todavía no tiene ningún control registrado. La barra se muestra con una altura mínima simbólica y el tooltip indica "Sin datos" en lugar de un porcentaje, para no confundirse con un 0% de cumplimiento real.

Al pasar el cursor sobre una barra aparece el nombre del dominio y, si tiene datos, el porcentaje exacto.

11. Exportar el inventario

La API expone un endpoint de exportación con el inventario completo aplanado:

GET http://localhost:3000/api/export?format=json — o format=csv

Actualmente el export se consume directamente desde la API (por ejemplo, pegando la URL en el navegador o vía curl); no hay un botón dedicado en la interfaz de usuario en esta versión.
